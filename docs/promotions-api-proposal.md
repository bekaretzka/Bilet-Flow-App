# Промокампании BiletFlow — предложение API

**Статус: предложено, ещё не согласовано с backend-командой.** Проверка документации проекта обнаружила лишь ожидаемый контракт кампаний в backend-api-gaps.md; согласованного API, OpenAPI и исходников backend/веб-клиента в checkout нет. Этот документ описывает минимальный контракт мобильного клиента и MockEngine, а не подтверждённый сервер. Создание скидок не подключает их применение при оформлении заказа.

## Доступ и маршруты

- GET /organizer/events/{event_id}/campaigns — список кампаний выбранного мероприятия.
- POST /organizer/events/{event_id}/campaigns — создание кампании.

Оба маршрута **новые, ещё не согласованные**, требуют Bearer access token. Доступ — только текущий владелец organizer profile мероприятия; назначение сотрудником проверки входа и чужая роль организатора не дают права. Мероприятие может быть draft, published или cancelled: на этом шаге создаются настройки, не активируется продажа. Сервер при каждом запросе проверяет существование события, владельца и связь кампании/типов с event_id. Общий refresh: один повтор только после явного 401, без транспортных повторов POST. Release использует настоящий Ktor-клиент и показывает фактическую ошибку отсутствующего маршрута; mock включается прежним debug-режимом.

## Создание

```json
{
  "name": "Ранняя регистрация",
  "code": "EARLY2027",
  "discount_type": "percent",
  "discount_value": 15,
  "starts_at": "2027-01-01T10:00:00+05:00",
  "ends_at": "2027-02-01T10:00:00+05:00",
  "usage_limit": 100,
  "ticket_type_ids": [1001,1002],
  "client_request_id": "68e78a71-d44e-4cff-a34a-296a7007ff32"
}
```

| Поле | Ограничение |
| --- | --- |
| name | Обязательно, 1–200 Unicode code points после trim |
| code | Обязательно, trim + uppercase, 3–32 ASCII символа: A–Z, 0–9, _, -; первый — буква или цифра |
| discount_type | percent или fixed |
| discount_value | Обязательное целое: percent — 1–100; fixed — 1–1 000 000 000 целых KZT (₸), не тиыны; модель Long |
| starts_at / ends_at | Обязательные ISO 8601 с Z или UTC-смещением, сравниваются как моменты; ends_at строго позже starts_at; допускаются прошлые/будущие периоды, связи с датами мероприятия этот минимальный контракт не требует |
| usage_limit | Необязательный int/null: null или отсутствие — без лимита; иначе 1–1 000 000. Ноль не означает бесконечность |
| ticket_type_ids | Необязательный массив положительных ID, default []; максимум 100, без дублей; [] — все текущие и будущие типы этого события |
| client_request_id | Обязательный UUID v4 одной логической отправки |

Каждый выбранный тип должен существовать и принадлежать выбранному мероприятию. Можно выбрать скрытый тип или тип черновика: это не делает его публичным и не даёт права купить. Форма использует полный организаторский GET /organizer/events/{event_id}/ticket-types со всеми страницами (его контракт также предложенный, см. backend-api-gaps.md), а не публичный список. Если список недоступен, форма сохраняется и предлагает повтор загрузки.

Уникальность code глобальная среди кампаний после нормализации, включая разные мероприятия и владельцев. Область уникальности — предложенное решение для согласования; код не переиспользуется на этом шаге. Коллизия — 409 CampaignCodeAlreadyExistsError с fields.code, без раскрытия чужого мероприятия. Для fixed сумма в этом шаге только сохраняется; ограничение скидки стоимостью покупки, совместимость скидок, округление процентов, резервирование/учёт использований и правила применения ожидают отдельного контракта checkout. Никаких локальных пересчётов стоимости заказа по этим данным сейчас нет.

## Успех и список

POST возвращает 201, серверный Campaign:

```json
{
  "id":12000,"event_id":101,"name":"Ранняя регистрация","code":"EARLY2027",
  "discount_type":"percent","discount_value":15,
  "starts_at":"2027-01-01T10:00:00+05:00","ends_at":"2027-02-01T10:00:00+05:00",
  "usage_limit":100,"ticket_type_ids":[1001,1002],
  "client_request_id":"68e78a71-d44e-4cff-a34a-296a7007ff32",
  "created_at":"2026-11-25T12:00:00+05:00"
}
```

GET: limit — int 1–100, default 50; cursor — непрозрачная строка следующей страницы. Формат принятого в проекте предложения пагинации: 200 {items: Campaign[], next_cursor: string|null}. Сортировка id DESC, стабильный keyset, курсор привязан к мероприятию и владельцу; сервер проверяет доступ на каждой странице. При смене контекста курсор не переиспользуется. Пустой ответ: {"items":[],"next_cursor":null}. Пример следующей страницы (строка курсора только пример, клиент её не строит):

```json
{"items":[{"id":12000,"event_id":101,"name":"Скидка 500 тенге","code":"KZT500","discount_type":"fixed","discount_value":500,"starts_at":"2027-01-01T10:00:00+05:00","ends_at":"2027-02-01T10:00:00+05:00","usage_limit":null,"ticket_type_ids":[],"client_request_id":"68e78a71-d44e-4cff-a34a-296a7007ff32","created_at":"2026-11-25T12:00:00+05:00"}],"next_cursor":null}
```

## Идемпотентность и ошибки

Уникальный ключ (current_user.id, event_id, client_request_id). Атомарно сохраняются кампания, глобальный уникальный code и результат операции. Повтор того же канонического тела возвращает прежние 201/ID/created_at без нового использования кода или новой кампании. Проверка повторного ключа предшествует проверке занятости кода; право владельца проверяется до выдачи результата. Другой body с прежним ключом — 409 ClientRequestConflictError. Канонизация: name trim, code trim+uppercase, ticket_type_ids отсортированы; отсутствующие optional равны null/[]; даты сравниваются как переданные строки после trim, разные написания одного момента могут считаться изменённым телом. Хранение ключа — срок жизни кампании, TTL/удаление согласуются отдельно.

Клиент хранит снимок body/UUID в памяти формы. При таймауте, обрыве или 5xx ручной повтор без правок использует его же. POST после транспортной ошибки автоматически не повторяется. Правка нормализованных данных или набора типов создаёт новую логическую отправку с новым UUID; предупреждение о возможном создании предыдущей кампании сохраняется. После успеха форма очищается и перечитывается первая страница списка. После закрытия формы, завершения процесса или смены аккаунта снимок не сохраняется; клиент не утверждает, что предыдущая операция не произошла.

| HTTP | Код | Действие |
| --- | --- | --- |
| 401 | detail / error,message | Общий refresh |
| 403 | EventAccessDeniedError | Возврат к профилю через существующую обработку прав |
| 404 | EventNotFoundError | Фактическая ошибка выбранного события |
| 422 | VALIDATION_ERROR | fields.name/code/discount_type/discount_value/starts_at/ends_at/usage_limit/ticket_type_ids/client_request_id; ошибки рядом с полями |
| 409 | CampaignCodeAlreadyExistsError | fields.code |
| 409 | ClientRequestConflictError | Тот же ключ с другим телом; автоматического нового POST нет |
| 5xx / сеть | error,message или detail | Сохранить форму, ручной повтор с тем же снимком |

```json
{"error":"VALIDATION_ERROR","message":"Validation failed","fields":{"ends_at":"Must be later than starts_at"}}
```

Клиент также поддерживает detail[].loc для ошибок полей. Ответы предыдущей сессии/события/формы игнорируются; токены и содержимое запросов не логируются. Ротация токенов в том же поколении сохраняет форму и снимок.

## MockEngine и границы

Состояние кампаний привязано к event_id; доступ проверяет владельца, ID типов сверяет с общим хранилищем, уникальность кода глобальная. Имя campaign-unknown симулирует потерю первого ответа после атомарного создания: повтор возвращает одну кампанию. campaign-offline — сетевой сбой до обработки. Переключатели только debug, не контрактные поля реального API. Данные живут до завершения mock-процесса.

Приёмка: процент/fixed KZT; null-лимит/[] типов; числовые и временные границы, смещения; чужие типы/аккаунт; глобальный повтор кода; одинаковый ключ/тело без дублей и изменённое тело с конфликтом; двойное нажатие/потеря ответа; пагинация/refresh/retry; смена аккаунта и поздние ответы. Реальная интеграция не подтверждена до проверки backend. Применение к заказу, Campaign QR, редактирование/удаление и отчётность находятся за рамками шага 51.
